# 开发与验证

当前源码版本为 0.8.17，Windows x64，使用 Python、Tkinter 与 Pillow。更新公告按版本列出面向使用者的变化，并保留作者署名。

## 运行

在仓库根目录，用包含 Tcl/Tk 的 Python 3.13 或 3.14 创建环境：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r src/requirements.txt
.venv\Scripts\python.exe src/run_pet.py
```

加 `--weixin` 可打开微信连接页。`desktop-dialogue.json` 默认选择 `s31r-o1b`，与当前桌面、微信试用配置一致；改成 `legacy` 可回到旧对话链路。配置变更在下次启动生效。

默认运行资料保存在本机 `data/`；可用环境变量 `SHIZUKA_DATA_DIR` 指向自己的既有目录。不要把个人设置、密钥、配对信息、收到的附件、真实聊天和记忆提交到仓库。

## 离线测试

```powershell
.venv\Scripts\python.exe -B tools/run_tests.py
```

测试入口使用临时数据目录，旧版用例固定使用 `legacy` 基线，新对话配置由对应测试显式选择，避免本机配置影响断言。公共仓库保留功能回归和合成测试资料；本地私人试聊、模型重放报告及历史对照快照不随源码上传。不能把离线测试通过当作角色口吻或真实微信投递效果已通过。

如果 Tk 在清理测试窗口时导致整个进程退出，可分模块运行以定位具体结果：

```powershell
.venv\Scripts\python.exe -B tools/run_tests_by_module.py
```

## 构建

```powershell
.venv\Scripts\python.exe -m pip install pyinstaller
.venv\Scripts\python.exe tools/package_test_release.py --kind desktop --build-root build/local-0817 --reports build/local-0817-reports --desktop-profile s31r-o1b
```

构建目录和输出包必须是新路径，脚本拒绝覆盖已有发布包。只复制允许的运行文件，不带入测试记录、个人资料或凭据；构建后运行冻结程序的离线检查并生成文件散列清单。

仓库根目录保留的 EXE、依赖、`version.json` 和对应清单来自已发布的 0.8.6，不是当前源码的构建产物。本轮 Git 更新不发布新的 GitHub Release，也不把本机测试包当作正式更新包；旧构建记录不能用于证明 0.8.17 的验证结果。

## 目前需要实测的部分

- 微信「正在输入」是否持续显示、分条回复之间是否正确保持，以手机端为准。
- 引用只能恢复微信提供的内容或本机已缓存的消息；升级前未缓存的旧引用可能需要重发。
- 原生语音条和视频尚未接入。Word 等文件可以保存，但当前聊天读取器只支持图片、文本/代码和 PDF。
- 主动搭话默认关闭，仍需真实网络环境下的长期连接测试。
- 角色口吻仍在调整，心情与精力的独立实验不等于已完整接入日常桌宠。
