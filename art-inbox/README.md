# 活动差分素材（art-inbox）

放"新的角色动作"原图的地方。等你这批图都生成好，我再把它们归一化成角色包能用的整身帧，
接进 `shizuka-side-motion` 的 `activity_frames`。

## 目录约定

```
art-inbox/
  <动作名>/
    原始-xxx.png                  ← 你生成的原图（透明底最好，白底我也能抠）
    帧-<动作名>-1000x943.png      ← 我归一化好的整身帧（可以直接进包）
    预览-<动作名>.png             ← 左：原立绘　右：新帧（并排对比）
    对比-<动作名>.png             ← 红=原立绘轮廓，青=新帧轮廓（看对齐）
```

## 关于"场景图"（`literature/原始-书桌查文献-修改版.webp`）——试过一版，已撤

按"整张全保留、当播报前的加载过渡图"做过一版：存在 `assets/loading_art.png`，
等回复 / 查资料时顶在她头顶上方淡入，带一行「让我查一下资料……」。

**实测不行，已经整段撤掉**（代码、资源、测试一起删）：

- 那张卡片是 `-topmost` 的独立窗口，尺寸有她身高的 1.15 倍（300px 上下），
  **正好压在她自己的聊天输入框上面**——看起来就像"聊天窗口变成了一张图"，
  而且把关闭按钮挡住，点不掉；
- 等回复时它还会一直挂着（模型慢的时候更明显），比原来的「…」小气泡重得多。

结论：这种"大图当加载提示"的做法不适合贴在角色身边。以后想用这张图，走**不挡人的位置**：
研究进展窗口里当配图，或者单独一个可以自己关掉的窗口。图还在 `art-inbox/literature/` 里留着。

## 归一化规则（脚本里已实现）

- 比例默认按 **`auto`**：优先匹配**头宽**（脸的大小最显眼），再用"头顶至少留 24px"限一层，
  避免人物变高后顶出画布。实测 `researching` 头宽与母图**完全一致**、脚底对齐 y=872。
- 头身比和母图不一致时（比如抱闹钟那张比母图"长腿"），她会比原来高一点（头顶高 31px），
  这是取舍：脸对齐 vs 身高对齐，只能选一个。想要完全一致就得**生成时用母图做参考图**，并写明"保持参考图一样的头身比"。
- **举着道具的图不能用头宽**：和服那张的伞盖跟头发在轮廓上连成一片，整身轮廓量出来 798px
  （真值大约 650~670，即伞把量出来的头宽撑大了一成多），按它缩会把她明显缩小。改用 `height` 模式
  （`normalize_activity.py listening height`）后，她落地高度 = 母图 798px，而且**眼睛正好落在母图的眼线 y=281**
  （两张图的脸都在自身高度的 26% 处，按身高对齐就自动对齐了眼线）。
- 脚本还留了个 `hair` 档（只认蓝紫头发色来量头宽）：对伞这张**不好使**——伞盖背光的暗紫和头发同色，
  量出来 757px 还是偏大。举道具的图一律走 `height`。

## 生成时的要求（照这个来，我这边几乎不用修）

1. **透明底**最好；白底、纯色底也行，我来抠。**别用复杂背景**（会抠不干净）。
2. **全身完整**：头顶到脚底都要在画面里，**别裁脚、别裁头发**，四周留一点空白。
3. **同一个角色、同一套衣服**：发型（深蓝短发 + 黄色发夹）、蓝白校服、格裙、深色过膝袜。
4. **姿势不要歪太多**：她平时是正面站着。低头看手机、举手、侧身一点都没问题，
   但别出现大幅度转身/躺倒（那会跟其他帧接不上）。
5. **比例尽量一致**：新图我会按"身高"缩放到母图（母图角色高 798px / 画布 1000×943）。
   实测这张的比例是 头宽比 0.644、身高比 0.641 —— 基本一致，说明造型没跑。
6. **同一个模型 + 同一个 seed** 出整组，一致性最好。
7. **别带文字、logo、水印**；效果线（比如这张左边那几条"嗡"）可以留，我会保留。
8. 分辨率 1000px 以上就够（我会缩到母图尺寸）。

## 归一化脚本

```powershell
& .venv\Scripts\python.exe build\normalize_activity.py <动作名>              # 默认 auto（先按头宽）
& .venv\Scripts\python.exe build\normalize_activity.py <动作名> height       # 举道具的图用这个
& .venv\Scripts\python.exe build\normalize_activity.py <动作名> hair         # 只认头发色量头宽（伞这张不好使）
```

它会：按选定比例缩放 → 用「头中轴与脚中轴的平均」对横轴 → 用脚底对纵轴 → 贴到 1000×943 透明画布，
再输出并排预览和叠色对比。角色包要求：**1000×943、RGBA、四角透明**（脚本会自动满足并校验）。

## 接进角色包时要改的东西（我这边）

已接好三张（`researching` / `reminder` / `listening`），做法是：

1. 帧文件放 `characters/shizuka-side-motion/activity/<状态名>.png`；
2. `character.json` 里挂 `"activity_frames": { "<状态名>": "activity/<状态名>.png", ... }`
   —— **给哪几张就生效哪几张**，没给的状态自动回落到常态立绘（不再要求凑齐 working/reminder/exit）；
3. 状态名登记在 `character_packs.ACTIVITY_STATES`，触发判定在 `activity_states.select_activity()`
   （优先级：鞠躬 > 拖动/下落/落地/摸头 > 等回答 > 待办提醒 > 放歌 > 查资料 > 文件任务）；
4. 之后再加新状态（`messaging` / `tutoring` / `drowsy`）就是：登记状态名 + 加一行触发 + 放一张帧，三处。
